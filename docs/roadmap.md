# ロードマップ

ジャンルに縛られない「カオスゲームエンジン」にするための計画です。全部を一度に作らず、毎回動くものを足していきます。

## 基本の考え方

### 共通語を決める

あらゆるジャンルの部品を混ぜても壊れないために、一番大事なのは部品の数ではありません。**部品同士が話す「共通語」を決めておくこと**です。

たとえば「ダメージ」の受け渡し方を1つに決めておけば、ソウルライクの剣で斬っても、ロボのミサイルが当たっても、ターン制の「たたかう」を選んでも、全部同じ `damage` という合図として届きます。受け取る側の「HP」部品は、誰に何をされたかを気にせず動けます。

共通語の候補:

- `damage` / `heal`: ダメージと回復
- `hp` / `dead`: 体力と死亡
- `team`: 陣営(味方・敵・中立)
- `interact`: 調べる、話しかける
- `pickup` / `use` / `equip`: 拾う、使う、装備する
- `flag`: フラグ、進行の記録
- `trigger`: イベントの発火

### 待てるスクリプト

ノベルやターン制を楽に書けるようにするための仕組みです。

```js
await ui.say('アリス', 'ここから先は危険よ');
const pick = await ui.choose(['進む', '戻る']);
if (pick === 0) await game.loadScene('戦闘');
```

「表示して、クリックを待って、次へ」が上から順に書けるようにします。

## 段階 3: ジャンルキット

各ジャンルの部品セットを、遊べるサンプルゲームと一緒に1つずつ足していきます。候補は [ideas.md](ideas.md) にまとめています。

最初のサンプルは、あえて**2つ以上のジャンルを混ぜたもの**にします。土台がちゃんと機能しているかを確かめるためです。

> 例: ノベルの会話の途中でロボが乱入し、ターン制バトルになり、勝ったら3Dの探索に戻る短い1本

## 注意点

- 部品が増えるとエディタで選べなくなるので、カテゴリ分けと検索が要ります
- 画像や音を使い始めると、ブラウザの保存領域(数MB)では足りなくなります
- 64 風のローポリな見た目を基本にすると、モデルファイルが不要になり軽く保てます
